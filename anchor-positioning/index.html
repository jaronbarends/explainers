Anchor positioning

Good resources: https://developer.chrome.com/docs/css-ui/anchor-positioning-api, https://www.joshwcomeau.com/css/anchor-positioning/

Anchor positioning basics

Anchor
I'm the target
  • A target element (positioned element) can be tethered to an anchor element
  • Create anchor element with anchor-name property (dashed ident)
  • Pull target out of document flow with position: fixed or position: absolute
  • Tie target to anchor element with position-anchor
  • Set position with position-area or anchor()
  • Anchor can have multiple targets
<div class="anchor">Anchor</div>
<div class="target">I'm the target</div>
.anchor {
  anchor-name: --my-anchor;
}

.target {
  position: fixed;
  position-anchor: --my-anchor;
  position-area: top;
}

When a page contains multiple anchors with the same anchor-name, a target that is associated with that anchor name (by its position-anchor property) will be tethered to the last anchor element in the source order.

To manage this, you can define an anchor-scope on an anchor's ancestor.

  • anchor-scope is defined on an anchor's ancestor
  • Only targets inside the same ancestor are allowed to tether to the specified anchor names
  • Scope can define all anchor names (anchor-scope: all) or only specific ones (anchor-scope: --my-anchor, --another-anchor) to be scoped

This is very useful for components that may occur multiple times on a page (or pages like this one where I don't want to have to come up with a unique name for every anchor). 

<div class="anchor-scope">
  <div class="anchor1">Anchor 1 …</div>
  <div class="anchor2">Anchor 2 …</div>

  <div class="target--anchor1-inside">…</div>
  <div class="target--anchor2-inside">…</div>
</div>

<div class="target--anchor1-outside">…</div>
<div class="target--anchor2-outside">…</div>

.anchor-scope {
  anchor-scope: --scoped-anchor;
}

.anchor1 {
  anchor-name: --non-scoped-anchor;
}

.anchor2 {
  anchor-name: --scoped-anchor;

.target--anchor1-inside,
.target--anchor1-outside {

.target--anchor1-inside,
.target--anchor2-inside {

Set position with position-area

  • Uses 9-cell grid based on the size of the anchor and the target (each target uses its own grid, not influenced by other positioned elements' sizes)
  • Physical (top, left) or logical (block-start, inline-end) values
  • Missing values will be treated as span-all
  • Use only physical (e.g. top right) or logical (e.g. block-start inline-end) values; mixing them (e.g. top inline-end) does not work
  • span-… means "center + specified value"
  • The div with bottom span-all is rendered on top op the anchor here.
    TL;DR: That won't happen when you trigger the anchor with a popover.
    When a target's containing block is a scroll container (the case here, because of position: fixed), and the target is outside view on initial render, the value used for bottom with position-area is zero-height, resulting in the target being positioned over the anchor. (See this very technical w3c discussion) That won't be recalculated when it scrolls into view, only when you re-trigger layout (for example by disabling/re-enabling position-area in the dev toolbar).
    See section on position: fixed vs position: absolute. 
.anchor {
    anchor-name: --my-anchor;
  }

  .target {
    position: fixed;
    position-anchor: --my-anchor;
  }

  .target--top {
    position-area: top; /* same as top span-all */
  }

  .target--span-bottom-right {
    max-width: 6rem; /* without max-width, elm will run on one line, so you won't see effect of span */
    position-area: span-bottom right;
  }

  .target--bottom-left {
    position-area: bottom left;
  }

Set position with the anchor() function

Anchor
top: anchor(top);
left: anchor(right);
bottom: anchor(center);
left: anchor(75%);
top: calc(anchor(center) + 1rem);
left: calc(anchor(left) + 1rem);
bottom: anchor(bottom);
right: anchor(center);

Syntax: <inset-value>: anchor(<anchor-name> <anchor-side>)

  • Positions the target relative to an anchor element
  • You can usually omit <anchor-name>. Element will then be positioned relative to its associated anchor element. (You only need to specify <anchor-name> if you want to position the element relative to another anchor element than its associated anchor element. Can't think of a use case for that)
  • <anchor-side> can also be center or a percentage of the anchor's width or height
  • anchor() returns a value, so you can use it in calc

Anchor positioning with popovers

UA stylesheet trips up positioning

Popover without UA stylesheet override

By default, the browser's stylesheet gives every popover an inset: 0; margin: auto; That centers it on screen, so anchor positioning doesn't work. 

<button class="anchor" popovertarget="popover-basic">Anchor …</button>
<div id="popover-basic" class="target popover" popover>…</div>

.popover {
  position: fixed;
  position-anchor: --my-anchor;
  /* does not work because of UA stylesheet */
  bottom: calc(anchor(top) + 0.5rem);
  left: anchor(center);
  translate: -50% 0;
}

Overriding browser stylesheet

Popover with UA stylesheet override

Set inset: auto; margin: 0; on the popover to position it relative to its anchor. 

<button class="anchor" popovertarget="popover-override">Anchor …</button>
<div id="popover-override" class="target popover" popover>…</div>

.popover {
  position: fixed;
  position-anchor: --my-anchor;
  inset: auto; /* override UA's inset: 0 */
  margin: 0; /* override UA's margin: auto */
  bottom: calc(anchor(top) + 0.5rem);
  left: anchor(center);
  translate: -50% 0;
}

Position fallbacks

Simple single fallback with flip-block or flip-inline

Anchor
Target with flip-block
Anchor
Target with flip-block
  • use position: fixed
  • add position-try: flip-block (or flip-inline)
  • margins will also flip
  • if you scroll back up, fallback position won't change back
  • For simple cases, specify only one direction for position-area (e.g. position-area: top and not position-area: top center), see below. 
.target {
  position: fixed;
  position-anchor: --my-anchor;
  position-area: top;
  position-try: flip-block;
  margin-bottom: 0.25rem;
}

Multiple fallbacks

Anchor
I'm the target

If you specify flip-inline and flip-block as a fallback, the browser picks only one of them, not both. So If you first scroll up, triggering the block flip, and then to the right, the inline flip will not be triggered. 

.target {
  position: fixed;
  position-anchor: --my-anchor;
  position-area: top left;
  position-try: flip-inline, flip-block;
}
Anchor
I'm the target

If you also specify the combination flip-inline flip-block, the it will trigger the second flip. 

.target {
  …
  position-try:
    flip-inline,
    flip-block,
    flip-inline flip-block;
}

Fallback concepts not covered

  • Use same kind of positioning (position-area: … or top: anchor(…)) for fallback
  • Custom fallback options with @position-try
  • Using position-area: top center and a target with a display: inline child will push target down over anchor instead of flipping
  • Container queries like @container anchored(fallback: bottom) {…} to check fallbacks
