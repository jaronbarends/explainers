View transitions

How the examples on this page work

Clicking the change-button will add the class samples--alt to this list of samples, changing the styling of the boxes.

View transitions 101

(A lot of this page's info comes from https://developer.chrome.com/docs/web-platform/view-transitions/same-document)

You start a view-transition by calling document.startViewTransition(() => updateTheDOMSomehow(data)). The callback function you pass to it is responsible for changing the DOM. When you call document.startViewTransition(), the browser creates snapshots of the page's current and new states. It then disables the page's interactions, and creates a tree of pseudo-elements containing the snapshots. It then animates those pseudo-elements, and finally removes them. The generated tree looks like this: 

::view-transition
└─ ::view-transition-group(root)
   └─ ::view-transition-image-pair(root)
      ├─ ::view-transition-old(root)
      └─ ::view-transition-new(root)

The ::view-transition pseudo-element sits in a separate layer over everything else on the page. In your developer tools, you'll find it between the html and the head. Although it acts visually as the "top-most layer" on the page during the transition, this view-transition layer is technically a rendering overlay, which is distinct from the browser's native Top Layer (used for dialog elements and popovers)

How this page's DOM update function works

On this page, all the samples are within a .samples container. the callback function simply toggles the class samples--alt on the container. For every sample I've defined how they should look when its ancestor does or doesn't have a samples--alt class. 

function toggleSamples(section) {
  if (section) {
    const samples = section.querySelector('.samples');
    if (!document.startViewTransition) {
      // fallback for browsers that don't have support
      toggleSamplesClass(data);
      return;
    }
    document.startViewTransition(() => toggleSamplesClass(samples));
  }
}

function toggleSamplesClass(samples) {
  samples.classList.toggle('samples--alt');
}

Basic transitions - transitioning all elements

If you don't specify anything, all elements of the page will be part of one single view-transition-group: the root view-transition-group.

The snapshot pairs (::view-transition-old(root) and ::view-transition-new(root)) smoothly transition from their old position and size to their new location, while their content crossfades.

As we'll see later, you can exclude elements from the root view-transition-group by giving them a view-transition-name.

Basic transitions of the root group

For the root group, it might seem as if only the content is crossfaded, and that translations are being ignored. That is not the case: the snapshot doesn't just contain the elements that have changed, but the entire page (except for elements with a view-transition-name), and the page's size or position doesn't change.

(or press 1) 
/* basic box - will be used across all samples;
here without view-transition-name */

.box {
	/* no view-transition-name specified */
	background: hotpink;

	.samples--alt & {
		background: yellowgreen;
	}
}
/* .box with additional class for moving */

.box.move {
	/* no view-transition-name specified */

  .samples--alt  & {
    /* will not animate in root transition group */
    transform: translateX(100%);
  }
}

Targeting individual elements and animating more props

You can exclude elements from the root view-transition-group by giving them a view-transition-name. Doing that will create a separate view-transition-group for that element. This has two advantages: you can specify a different animation for that element, and you can animate more of its properties.

The resulting tree looks like this:

::view-transition
├─ ::view-transition-group(root)
│  └─ ::view-transition-image-pair(root)
│     ├─ ::view-transition-old(root)
│     └─ ::view-transition-new(root)
└─ ::view-transition-group(some-name)
   └─ ::view-transition-image-pair(some-name)
      ├─ ::view-transition-old(some-name)
      └─ ::view-transition-new(some-name)

Every view-transition-groups will be animated separately. For every group, the browser will check if their position or size changes, and tries to animate that. If the position or size doesn't change, it will animate the opacity. (To be precise: the view-transition-old and view-transition-new elements will get an animation that is defined by the User Agent style sheet. That animation changes the opacity)

(or press 2)

root: animate opacity

.box.move {
	/* no view-transition-name specified */

  .samples--alt  & {
    transform: translateX(100%);
  }
}

Every element that doesn't have a view-transition-name will be part of the root view-transition, which contains the entire page. Since the page's position won't change, this only animates the ::view-transition-old(root)'s opacity from 1 to 0, and the ::view-transition-new(root)'s opacity from 0 to 1.

specific name: animate animatable props

.box.move.has-transition-name {
	/* every view-transition-name has to be unique */
	view-transition-name: box-move;
}

When you set a view-transition-name on an element, all of its animatable properties are animated - in this case background and transform. You don't have to specify anything else.

This creates a separate tree of view-transition pseudo-elements for this element.

The browser checks if a transition-group's position or size changes, and tries to animate that. It looks at the root view-transition as a whole; that contains the entire page, and that doesn't change position or size. Adding a view-transition-name to an element, makes the browser looks at the properties of that single element, and those it can animate.

Adjusting duration

(or press 3)

The default duration is set in the browsers User Agent style sheet: 

/* UA style sheet */
::view-transition-group(*) {
	duration: 0.25s;
}

Its descendants ::view-transition-image-pair(*), ::view-transition-old(*) and ::view-transition-new(*) all inherit that duration.

You can overrule the duration for a specific view-transition-name's ::view-transition-group: 

.box.adjusted-duration {
  view-transition-name: adjusted-duration;
}

::view-transition-group(adjusted-duration) {
  animation-duration: var(--duration);
}

Default duration

.box.move.has-transition-name-2 {
	view-transition-name: box-move-2;
	/* no animation-duration specified for this group so will use default value */
}

Adjusted duration

.box.move.adjusted-duration-2 {
	/* every view-transition-name has to be unique */
	::view-transition-group(adjusted-duration-2) {
		animation-duration: var(--duration);
	}
}

Be very careful with changing a view-transition-group's duration. Note that the startViewTransition function is called on the document. It then disables the page's interactions, runs the transitions on all elements that have a view-transition-name - no matter if those elements have changed or not. When all transitions are done, the page's interactions are re-enabled. That means that if you have any transition with a longer duration, the entire page is frozen until that transition is done.

Pseudo-elements that can be animated

(or press 4)

During a view transition, there's actually a tree of four nested pseudo-elements: 

::view-transition-group(name)
└── ::view-transition-image-pair(name)
		├── ::view-transition-old(name)
		└── ::view-transition-new(name)

This is a simple box with just a view-transition-name specified:

.box.move.has-transition-name-section-4 {
	view-transition-name: section-4-sample-1;
}

Here, there are actually three separate pseudo elements that get their own animations applied:

  • The ::view-transition-group's animation handles only a few properties: those having to do with position, size and opacity.
  • The ::view-transition-old's animation fades its pseudo-element out
  • The ::view-transition-new's animation fades its pseudo-element in

(When you set a duration that's long enough to be able to inspect the different pseudo elements in the developer tools, you can see that these are animations with names like -ua-view-transition-fade-out, -ua-mix-blend-mode-plus-lighter that are defined in the user agent stylesheet)

Animate the ::view-transition-image-pair

You can add a separate animation to the ::view-transition-image-pair, that will affect the pseudo-element within the ::view-transition-group: 

.box.move.scale {
  view-transition-name: box-move-scale;
}

@keyframes scale-down {
  0% { scale: 1; }
  50% { scale: 0.7; }
  100% { scale: 1; }
}

::view-transition-image-pair(box-move-scale) {
  animation: scale-down ease-in-out;
  animation-duration: inherit;
}

The examples I've come across animate ::...-old and ::...-new instead of ::...image-pair. See next section for that.

Adding outlines for clarity

To understand better what's going on, I've added outlines to the ::view-transition-group and the ::view-transition-image-pair: 

.box.move.scale.has-outline {
  view-transition-name: box-move-scale-has-outline;
}

::view-transition-group(box-move-scale-has-outline) {
  outline: 4px solid black;
}

::view-transition-image-pair(box-move-scale-has-outline) {
  animation: scale-down ease-in-out;
  animation-duration: inherit;
  outline: 4px solid deepskyblue;
}

Animating ...-image-pair vs ...-old and ...-new

Most examples I've come across do not animate the ::view-transition-image-pair, but animate the ::view-transition-old and ::view-transition-new (with the same animation) instead.

By default, the ...-old and ...-new pseudo-elements respectively have a fade-out and a fade-in animation. When you overwrite those animations, the fading effects are also overwritten. In that case, the ...-new pseudo-element is fully visible as soon as the view-transition starts. And it will be on top of ...-old, because it comes after it in the dom.

So in the example here, you'll never see the ...-old pseudo-element with the blue outline, only the ...-new pseud-element with the orange outline. 

.box.move.scale-old-new.has-outline {
  view-transition-name: box-move-scale-old-new-has-outline;
}

::view-transition-old(box-move-scale-old-new-has-outline),
::view-transition-new(box-move-scale-old-new-has-outline) {
  animation: scale-down ease-in-out;
  animation-duration: inherit;
  outline: 4px solid deepskyblue;
}
::view-transition-new(box-move-scale-old-new-has-outline) {
  outline-color: orange;
}

Using different animations for ...-old and ...-new

In theory, you could use different animations for ::view-transition-old and ::view-transition-new. Don't know why you would want to, but you can ;)
I've slightly reduced the ...-old and ...-new's opacity in this example, so you can still see the containing ...-group 

.move.scale-old-new-independently.has-outline {
	view-transition-name: scale-old-new-independently;
}

::view-transition-group(scale-old-new-independently) {
	outline: 4px solid black;
}

::view-transition-old(scale-old-new-independently),
::view-transition-new(scale-old-new-independently) {
	animation: scale-up ease-in-out;
	animation-duration: inherit;
	outline: 4px solid deepskyblue;
	opacity: 0.7;
}
::view-transition-new(scale-old-new-independently) {
	animation-name: scale-down;
	outline-color: orange;
}

Note that the old and new snapshots aren't the same kind of element as the box whose style is changing. The snapshots are replaced elements (similar to an img). That means that you can only animate some of their properties (size, position, opacity, etc), but not others (like background, color).

Custom duration for ::...-image-pair

(or press 5)

You can specify a different duration for the ::view-transition-image-pair, to make its animation continue after the ::view-transition-group's animation has finished.

In this example, the translation is set on the div.box.move. That is handled by the ::view-transition-group's transition, which has the default duration of 250ms. The scaling animation is set on the ::view-transition-image-pair. Setting that pseudo-element's duration to 500ms makes the animation look nicer. 

@keyframes scale-down-bounce {
	0% { scale: 1; }
	25% { scale: 0.8; }
	60% { scale: 1.1; }
	80% { scale: 0.95; }
	100% { scale: 1; }
}

.move.scale-async {
	view-transition-name: box-move-scale-async;
}

::view-transition-image-pair(box-move-scale-async) {
	animation: scale-down-bounce var(--duration) ease-in-out;
}

Gotchas

All transitions always run; get cleaned up when last one finishes

When you call document.startViewTransition(callbackFn), all view transitions that are defined will be run; not just the ones that have changed because of the callback function. The cleanup that removes all the pseudo-elements will only be done after all animations have finished. You can see this clearly when you set the --duration-async variable in the section "Custom duration for ::...-image-pair" to a higher value, and then trigger the examples with a border in the "Pseudo-elements that can be animated" section. The borders will be visible until the other section's animation is finished, even though there is no visible change to that other section.

Custom properties in view-transitions

if you want to use a css var in view-transition (like we do with --duration on this page), it has to be defined at :root. This is because the pseudo elements are part of the document, not of the body. For setting with js, use document.documentElement.style.setProperty('--some-prop', value);

Static vs live representation in snapshots

Earlier, I said that the browser creates snapshots of the old and new states of the page. There's a small nuance in that: ::view-transition-old(root) is a screenshot of the old view, and ::view-transition-new(root) is a live representation of the new view. That means that if you transition a <video /> element, the ::...-old element contains a static image of the video, where the ::...-old element renders a playing video. Both render as CSS 'replaced content' (like an <img />).
