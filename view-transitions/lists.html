Practical examples of view transitions

For most of the examples, We'll add items at the 2nd place in the list

Basic: view-transition-name on list element

  • Item one

I'm a <p> after the list

The most basic transition is to just give a view-transition-name to the list. Then the complete old and new states simply crossfade in the set --duration. If you always add the item to the end of the list that is fine: it looks like only that list-item fades in.

The <p> after the list is not part of the named view-transition, but of the root view-transition. That causes it to get its new position with the browser's default duration of 0.25s 

<ul class="list-basic">...</ul>
.list-basic {
  view-transition-name: list-basic;
}
::view-transition-group(list-basic) {
  animation-duration: var(--duration-list-basic);
}

Inserting items in the middle

When we add list items in the middle of the list (like here: always at position 2) setting a view-transition-name on the list-element doesn't work well: since the old and new states of the entire list crossfade, you see the list-items crossfade into each other.

Animating items separately: view-transition-name on list items

  • Item one

I'm a <p> after the list

You can make the list-items animate separately if you give each of them their own view-transition-name, like this: 

<li style="view-transition-name: list-item-name-on-li-1">Item one</li>
<li style="view-transition-name: list-item-name-on-li-2">Item one</li>

And then, for every item you add dynamically, set it with JavaScript:

item.style.viewTransitionName = `list-item-name-on-li-${id}`;

To define the animation for all these view-transition-names, you can pass something else than the view-transition-name to the ::view-transition-... pseudo-element: a view-transition-class, preceded with a dot .. This will work on all ::view-transition-... pseudo-elements. 

li {
  view-transition-class: name-on-li;
}

::view-transition-group(.name-on-li) {
  animation-duration: var(--duration-name-on-li);
}

Gotchas and pitfalls

Separate definitions no longer necessary

When view-transition-class was not yet supported, you needed to define the animation for each view-transition-name separately like this: 

/* Don't do it like this - error-prone and not DRY*/
::view-transition-group(list-item-name-on-li-1),
::view-transition-group(list-item-name-on-li-2),
::view-transition-group(list-item-name-on-li-3),
::view-transition-group(list-item-name-on-li-4) {
  animation-duration: var(--duration-name-on-li);
}

That's both annoying and error-prone, because you don't know how many items might be added to your list. You may still come across this in other examples on the internet.

Don't use nth-child selectors

You can't use nth-child selectors like this:

.my-list > nth-child(1) {
  /* won't work */                  
  view-transition-name: list-item-name-on-li-1;
}

In that case, you don't tie the view-transition-name to a specific node, but it will be assigned to node that matches the given position in the DOM. That's why we're using JavaScript to add the view-transition-name in the code earlier in this example. This practice of making the name follow the element, not the position, is called the stable identity pattern for view transitions.

Passive participation in view transitions

In this example, the list-items keep their view-transition-names after they are inserted. That has an unwanted side effect: when those elements' positions change due a view transition somewhere else in the DOM, that position change will also be animated.

This is usually not what you want. You can prevent it by dynamically adding the view-transition-names before the transition starts, and removing them when the animation finishes — see the next section.

Dynamically adding and removing view-transition-names

  • Item 1

I'm a <p> after the list

To get the cleanest effect and to prevent elements being affected by view transitions on other elements, you can dynamically add and remove the view-transition-names. 

  const list = document.getElementById('list-dynamic-names');
  // children is an HTMLCollection that does not have forEach, so convert to array
  let lis = [...list.children];
  const transitionNameBase = 'list-item-dynamic-names';
  lis.forEach((li, idx) => {
    li.style.viewTransitionName = `${transitionNameBase}-${idx}`;
  });

  const newLi = document.createElement('li');
  newLi.textContent = `Item ${list.children.length + 1}`;
  newLi.style.viewTransitionName = `${transitionNameBase}-new`;

  // in real-world code, add fallback
  const transition = document.startViewTransition(() => {
    const firstLi = list.querySelector('li');
    firstLi.after(newLi);
  });

  transition.finished.then(() => {
    lis.forEach((li, idx) => {
      li.style.viewTransitionName = 'none';
    });
    newLi.style.viewTransitionName = 'none';
  });

.list-dynamic-names > li {
  /* multiple items; use view-transition-class. this doesn't
  do anything until view-transition-name is added to element */
  view-transition-class: dynamic-names;
}

::view-transition-group(.dynamic-names) {
  animation-duration: var(--duration-dynamic-names);
}

Now when another element is added with a view transition, this no longer affects the list items.

No css needed if default animation is fine

Note that we have only added the css here to be able to change the view-transition's animation-duration. If you're fine with the default animation (250ms, crossfade and position), then we don't need any css except for the view-transition-names that we're adding with JavaScript.
