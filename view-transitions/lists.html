Practical examples of view transitions

For most of the examples, we'll add items at the 2nd place in the list

Basic: view-transition-name on list element

  • Item one

I'm a <p> after the list

The most basic transition is to just give a view-transition-name to the list. Then the complete old and new states simply crossfade in the set --duration. If you always add the item to the end of the list that is fine: it looks like only that list-item fades in.

The <p> after the list is not part of the named view-transition, but of the root view-transition. That causes it to get its new position with the browser's default duration of 0.25s 

<ul class="section-basic__list">...</ul>
.section-basic__list {
  view-transition-name: section-basic__list;
}

::view-transition-group(section-basic__list) {
  animation-duration: var(--duration-section-basic);
}

I'm a <p> after the list

Inserting items in the middle

When we add list items in the middle of the list (like here: always at position 2) setting a view-transition-name on the list-element doesn't work well: since the old and new states of the entire list crossfade, you see the list-items crossfade into each other.

Animating items separately: view-transition-name on list items

  • Item one

I'm a <p> after the list

You can make the list-items animate separately if you give each of them their own view-transition-name, like this: 

<li style="view-transition-name: section-name-on-li__item-1">Item one</li>
<li style="view-transition-name: section-name-on-li__item-2">Item one</li>

And then, for every item you add dynamically, set it with JavaScript:

item.style.viewTransitionName = `section-name-on-li__item-${id}`;

To define the animation for all these view-transition-names, you can pass something else than the view-transition-name to the ::view-transition-... pseudo-element: a view-transition-class, preceded with a dot .. This will work on all ::view-transition-... pseudo-elements. 

.section-name-on-li__list > li {
  view-transition-class: section-name-on-li;
}

::view-transition-group(.section-name-on-li) {
  animation-duration: var(--duration-section-name-on-li);
}

Gotchas and pitfalls

Separate definitions no longer necessary

When view-transition-class was not yet supported, you needed to define the animation for each view-transition-name separately like this: 

/* Don't do it like this - error-prone and not DRY*/
::view-transition-group(section-name-on-li__item-1),
::view-transition-group(section-name-on-li__item-2),
::view-transition-group(section-name-on-li__item-3),
::view-transition-group(section-name-on-li__item-4) {
  animation-duration: var(--duration-name-on-li);
}

That's both annoying and error-prone, because you don't know how many items might be added to your list. You may still come across this in other examples on the internet.

Don't use nth-child selectors

You can't use nth-child selectors like this:

.my-list > nth-child(1) {
  /* won't work */                  
  view-transition-name: section-name-on-li__item-1;
}

In that case, you don't tie the view-transition-name to a specific node, but it will be assigned to node that matches the given position in the DOM. That's why we're using JavaScript to add the view-transition-name in the code earlier in this example. This practice of making the name follow the element, not the position, is called the stable identity pattern for view transitions.

Passive participation in view transitions

In this example, the list-items keep their view-transition-names after they are inserted. That has an unwanted side effect: when those elements' positions change due a view transition somewhere else in the DOM, that position change will also be animated.

This is usually not what you want. You can prevent it by dynamically adding the view-transition-names before the transition starts, and removing them when the animation finishes — see the next section.

Dynamically adding and removing view-transition-names

  • Item 1

I'm a <p> after the list

To get the cleanest effect and to prevent elements being affected by view transitions on other elements, you can dynamically add and remove the view-transition-names. 

const list = document.getElementById('section-dynamic-names__list');
// children is an HTMLCollection that does not have forEach, so convert to array
let lis = [...list.children];
const transitionNameBase = 'section-dynamic-names__item';
lis.forEach((li, idx) => {
  li.style.viewTransitionName = `${transitionNameBase}-${idx}`;
});

const newLi = document.createElement('li');
newLi.textContent = `Item ${list.children.length + 1}`;
newLi.style.viewTransitionName = `${transitionNameBase}-new`;

// in real-world code, add fallback
const transition = document.startViewTransition(() => {
  const firstLi = list.querySelector('li');
  firstLi.after(newLi);
});

transition.finished.then(() => {
  lis.forEach((li) => {
    li.style.viewTransitionName = 'none';
  });
  newLi.style.viewTransitionName = 'none';
});

.section-dynamic-names__list > li {
  /* multiple items; use view-transition-class. this doesn't
  do anything until view-transition-name is added to element */
  view-transition-class: section-dynamic-names;
}

::view-transition-group(.section-dynamic-names) {
  animation-duration: var(--duration-section-dynamic-names);
}

Now when another element is added with a view transition, this no longer affects the list items.

No css needed if default animation is fine

Note that we have only added the css here to be able to change the view-transition's animation-duration. If you're fine with the default animation (250ms, crossfade and position), then we don't need any css except for the view-transition-names that we're adding with JavaScript.

Separate animation for inserted items

  • Item 1

I'm a <p> after the list

To add a different animation for the inserted item, the new item shouldn't use the same view-transition-class as the existing items, but get its own animation based on its view-transition-name. 

const list = document.getElementById('section-entry-animation__list');
// children is an HTMLCollection that does not have forEach, so convert to array
const lis = [...list.children];
lis.forEach((li, idx) => {
  li.style.viewTransitionName = `section-entry-animation__item-existing-${idx}`;
});

const newLi = document.createElement('li');
newLi.style.viewTransitionName = 'section-entry-animation__item-inserted';
newLi.textContent = `Item ${list.children.length + 1}`;

// in real-world code, add fallback
const transition = document.startViewTransition(() => {
  const firstLi = list.querySelector('li');
  firstLi.after(newLi);
});

transition.finished.then(() => {
  lis.forEach((li) => {
    li.style.viewTransitionName = 'none';
  });
  newLi.style.viewTransitionName = 'none';
});

.section-entry-animation__list > li {
  /* multiple items; use view-transition-class. this doesn't
  do anything until view-transition-name is added to element */
  view-transition-class: section-entry-animation__item-existing;
}

@keyframes scale {
  0% {
    scale: 1;
  }
  50% {
    scale: 0.95;
  }
  100% {
    scale: 1;
  }
}

@keyframes slide-in {
  from {
    translate: -20%;
    opacity: 0;
  }
}

::view-transition-image-pair(.section-entry-animation__item-existing) {
  animation: scale ease-in-out both;
  animation-duration: 0.5s;
}

::view-transition-group(section-entry-animation__item-inserted) {
  animation: slide-in ease-out both;
  animation-duration: var(--duration-section-entry-animation__item-inserted);
  animation-delay: 0.25s;
}

::view-transition-image-pair(section-entry-animation__item-inserted) {
  /* override ::view-transition-image-pair(.section-entry-animation__item-existing) */
  animation: none;
}

Gotchas and pitfalls

Use ::view-transition-image-pair for scaling

We're animating the existing items' scale. In that case, you can't put the animation on the ::view-transition-group. You should only use that only for position, size and timing. Put it on ::view-transition-image-pair instead.

Override new item's ::view-transition-image-pair styles

We're assigning view-transition-class: section-entry-animation__item-existing; to .section-entry-animation__list > li. When the new item is inserted, it also matches that selector. That means that even though we are using ::view-transition-group(section-entry-animation__item-inserted) here, the styles for ::view-transition-image-pair(.section-entry-animation__item-existing) are also applied. We need to override that by setting the animation for ::view-transition-image-pair(section-entry-animation__item-inserted) to none. Both rules have the same specificity, so the code order determines the outcome.

An alternative would have been not to use ::view-transition-group(section-entry-animation__item-inserted) at all, and put the animation directly on ::view-transition-image-pair(section-entry-animation__item-inserted). I have not done that here for the sake of pointing out this pitfall.

Only animate items after inserted item

The animation would look better if we would only animate the existing items that come after the inserted item. To do that, just don't add a view-transition-name to the existing items coming before it.

Animate inserted and removed items

  • Item 1

I'm a <p> after the list

If you want entry and exit animations, a lot stays the same compared to the previous example: you still need to add ::view-transition-names to the existing items and the inserted or removed item. However, the timing is slightly different: on entry, you want the existing items to move down first and then start the animation for the inserted item. On exit, it's the other way around. To accomplish that, we need to define separate view-transition-classes for the existing items, and separate view-transition-names for the inserted or removed item. 

function addTransitionNamesAndClass({ list, transitionNameBase, transitionClass }) {
  // children is an HTMLCollection that does not have forEach, so convert to array
  let lis = [...list.children];
  lis.forEach((li, idx) => {
    li.style.viewTransitionClass = transitionClass;
    li.style.viewTransitionName = `${transitionNameBase}-${idx}`;
  });
}

function removeTransitionNames(list) {
  let lis = [...list.children];
  lis.forEach((li) => {
    li.style.viewTransitionName = 'none';
  });
}

function sectionEntryExit_addItem() {
  const list = document.getElementById('section-entry-exit__list');
  addTransitionNamesAndClass({
    list,
    transitionNameBase: 'section-entry-exit__item-existing',
    transitionClass: 'section-entry-exit__item-existing--with-entry',
  });

  const newLi = document.createElement('li');
  newLi.style.viewTransitionName = 'section-entry-exit__item-inserted';
  newLi.innerHTML = `Item ${list.children.length + 1}`;

  const transition = document.startViewTransition(() => {
    const firstLi = list.querySelector('li');
    firstLi.after(newLi);
  });
  transition.finished.then(() => {
    removeTransitionNames(list);
  });
}

function sectionEntryExit_removeItem(liToRemove) {
  const list = document.getElementById('section-entry-exit__list');
  addTransitionNamesAndClass({
    list,
    transitionNameBase: 'section-entry-exit__item-existing',
    transitionClass: 'section-entry-exit__item-existing--with-exit',
  });

  liToRemove.style.viewTransitionName = 'section-entry-exit__item-removed';
  const transition = document.startViewTransition(() => {
    liToRemove.remove();
  });
  transition.finished.then(() => {
    removeTransitionNames(list);
  });
}

When a new item is inserted (on entry), the existing items get the view-transition-class of section-entry-exit__item-existing--with-entry, and the inserted item gets the view-transition-name of section-entry-animation__item-inserted.

When an item is removed (on exit), the existing items get the view-transition-class of section-entry-exit__item-existing--with-exit, and the inserted item gets the view-transition-name of section-entry-animation__item-removed.

Gotchas and pitfalls

Add scaling to ::...-image-pair but timing to ::...-group

The existing items have a scaling animation. We can't apply that to ::view-transition-group, because that messes with its positioning, so we use ::view-transition-image-pair instead. It would seem logical to add the animation-duration and animation-delay their as well, but the ::...-group has its own animation that takes care of the position update. So then the ::...-group's animation would start rightaway, and the ::...-image-pair after the delay. To prevent that, add the animation-duration and animation-delay to the ::...-group; the ::...-image-pair will inherit those settings by default. 

.section-entry-exit__list > li {
  display: flex;
  justify-content: space-between;
}

::view-transition-group(.section-entry-exit__item-existing--with-entry),
::view-transition-group(.section-entry-exit__item-existing--with-exit) {
  animation-duration: 0.5s;
}

::view-transition-group(.section-entry-exit__item-existing--with-exit) {
  animation-delay: var(--duration-section-entry-exit);
}

::view-transition-image-pair(.section-entry-exit__item-existing--with-entry),
::view-transition-image-pair(.section-entry-exit__item-existing--with-exit) {
  animation: scale ease-in-out both;
}

::view-transition-group(section-entry-exit__item-inserted),
::view-transition-group(section-entry-exit__item-removed) {
  animation: slide-in ease-out both;
  animation-duration: var(--duration-section-entry-exit);
  animation-delay: 0.25s;
}
::view-transition-group(section-entry-exit__item-removed) {
  animation-direction: reverse;
  animation-delay: 0s;
}

::view-transition-image-pair(section-entry-exit__item-inserted),
::view-transition-image-pair(section-entry-exit__item-removed) {
  /* override
  ::view-transition-image-pair(.section-entry-exit__item-existing--with-entry) and
  ::view-transition-image-pair(.section-entry-exit__item-existing--with-exit) */
  animation: none;
}
