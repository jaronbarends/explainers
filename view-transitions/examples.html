Practical examples of view transitions

For each of the examples, We'll add items at the 2nd place in the list

  • Item one

I'm a <p> after the list

Basic: view-transition-name on list element

The most basic transition is to just give a view-transition-name to the list. Then the complete old and new states simply crossfade in the set --duration. If you always add the item to the end of the list that is fine: it looks like only that list-item fades in.

The <p> after the list is not part of the named view-transition, but of the root view-transition. That causes it to get its new position with the browser's default duration of 0.25s 

<ul class="list-basic">...</ul>
.list-basic {
  view-transition-name: list-basic;
}
::view-transition-group(list-basic) {
  animation-duration: var(--duration);
}

Inserting items in the middle

When we add list items in the middle of the list (like here: always at position 2) setting a view-transition-name on the list-element doesn't work well: since the old and new states of the entire list crossfade, you see the list-items crossfade into each other.

I'm a <p> after the list

view-transition-name on list-items

You can make the list-items animate separately if you give each of them their own view-transition-name, like this: 

#list-item-name-on-li-1 {
  view-transition-name: list-item-name-on-li-1;
}
...
#list-item-name-on-li-4 {
  view-transition-name: list-item-name-on-li-4;
}

::view-transition-group(list-item-name-on-li-1),
::view-transition-group(list-item-name-on-li-2),
::view-transition-group(list-item-name-on-li-3),
::view-transition-group(list-item-name-on-li-4) {
  animation-duration: var(--duration-name-on-li);
}

You can't use nth-child selectors like this:

.my-list > nth-child(1) {
  /* won't work */                  
  view-transition-name: list-item-name-on-li-1;
}

In that case, you don't tie the view-transition-name to a specific node, but it will be assigned to node that matches the given position in the DOM.

So, you'll have to set a something like an id on the inserted list items to tie the name to the specific node. And if you're already doing that, you can also add the name itself with JavaScript: 

item.style.viewTransitionName = `list-item-name-on-li-${id}`;

This practice of making the name follow the element, not the position, is called the stable identity pattern for view transitions.

Prevent repetition with view-transition-class

Earlier in this example, we defined the animation for each view-transition-group, even though they had the same animation: 

/* error-prone and not DRY */
::view-transition-group(list-item-name-on-li-1),
::view-transition-group(list-item-name-on-li-2),
::view-transition-group(list-item-name-on-li-3),
::view-transition-group(list-item-name-on-li-4) {
  animation-duration: var(--duration-name-on-li);
}

That's both annoying and error-prone, because you don't know how many items might be added to your list. To prevent this, you can specify a view-transition-class, and pass that (preceded with a .) to the pseudo-element selector instead of a name: 

li.list-name-on-li {
  view-transition-class: name-on-li;
}

::view-transition-group(.name-on-li) {
  animation-duration: var(--duration-name-on-li);
}

This will work on all ::view-transition-... pseudo-elements.

Passive participation in view transitions

In this example, the list-items keep their view-transition-names. That has an unwanted side effect: when those elements' positions change due a change somewhere else in the DOM, that position change will also be animated. To see this, first add a few items in this section's list; then add an item in the list in the section above it. That added item will push this section down, resulting in an animation on its list items.
